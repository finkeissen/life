# Work Cycle — life / BEING
Stand: 2026-03-08

## Phase
Übergang von Architektur → erste tragfähige Projektionen.

Der Core (`life`) gilt vorläufig als ausreichend stabil.

Core-Änderungen erfolgen nur noch, wenn eine Projektion strukturell daran scheitert.

---

# Arbeitsrhythmus (2–4 Wochen)

## Zyklus
1. kleine Projektion bauen
2. prüfen, ob sie die Invarianten trägt
3. Blindheiten dokumentieren
4. ggf. Core präzisieren
5. nächste Projektion

---

# Erste konkrete Aufgaben

## 1. Source Map erstellen

Datei:
`source_map.md`

Ziel:
Explizit festhalten, welche früheren Arbeiten welche Teile des Core speisen.

Struktur:

Quelle → Core-Komponente → Status

Status:
- integriert
- teilweise integriert
- Hintergrund
- noch zu extrahieren

---

## 2. Erste Projektion bauen

Ziel:
Ein erstes kleines, echtes Artefakt.

Form:
eine narrative Szene.

Umfang:
ca. 5–15 Seiten.

---

## Szenen-Kriterium

Die Szene muss mindestens eine der zentralen Invarianten sichtbar machen:

- Welt > Bewusstsein
- Irreversibilität von Entscheidungen
- nicht delegierbare Verantwortung
- strukturelles Scheitern
- Entwicklung unter Begrenztheit

---

## 3. Projection Template definieren

Neue Datei:

`projection_template.md`

Fragen:

- Welche Core-Invarianten werden sichtbar?
- Welche werden ausgeblendet?
- Welche Verzerrungen entstehen durch das Medium?
- Was kann dieses Medium sichtbar machen, was andere nicht können?

---

## 4. Ergebnis dokumentieren

Nach jeder Projektion:

`projection_log.md`

Einträge:

- Was hat funktioniert?
- Wo ist das Framework kollabiert?
- Welche Blindheiten wurden sichtbar?

Nur wenn nötig:
Core präzisieren.

---

# Leitregel

Nicht versuchen, das Leben vollständig zu erklären.

Stattdessen prüfen:

Trägt das Framework konkrete menschliche Situationen?
